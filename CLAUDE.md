# Unrect

## Status

This project is experimental, but both the substrate (`ISpace`, `Plane`, `Point`, the strategy/scan/landmark interfaces) and the projection layer (`Unrect.Projections`, one vocabulary — `ProjectionBuilders<TSpace>`) now have deliberate, review-hardened semantics pinned by `src/Unrect.Tests` (xUnit, 2,289 tests) and `src/Unrect.Analyzers.Tests` (18 tests). Run `dotnet test src/Unrect.sln`; keep it green. Gate builds with `dotnet build src/Unrect.sln -v q --no-incremental` — incremental builds silently skip analyzer diagnostics (xUnit analyzers etc.), so a plain build can report 0 warnings while warnings exist.

## Problem Domain

Unrect addresses a real-world problem common in financial institutions: hierarchical data stored in flat 2D structures (primarily Excel spreadsheets). These are not simple tabular datasets — they contain nested, heterogeneous regions that need to be parsed into structured objects.

A typical example is an IRR report with:
- A header section (title, date, generic report info)
- Repeating client blocks, one per client
- Within each client block, sub-sections like capital calls, fundings, etc.

Row-oriented parsers are the wrong tool for this. They devolve into stateful cursor logic and fragile index tracking. Unrect takes a different approach: declarative 2D spatial decomposition. You describe the shape of the data once, and the framework handles decomposing the grid along that shape and projecting each part to a typed object.

## Design Philosophy: Declarative, Not Imperative

This is the core design commitment of the project, and it constrains every API decision.

A user of Unrect **declares the shape** of the data — "a header, then N repeating client blocks, each containing a capital-calls section sized by this predicate" — as a static description built from shapes and strategies. The framework interprets that description to perform the decomposition. The user never writes traversal logic: no "current row" state, no manual index arithmetic, no loops that walk the grid deciding what comes next. (`LayoutCursor` is a cursor in name only: `Next` declares the next child in flow order and hands back what it read, and exposes no position to compute with; the lambda runs once at declaration, before any space exists, with each child reading as the empty value of its type, and once per application with the values.)

The distinction matters because the imperative alternative is the failure mode this project exists to escape. Row-oriented parsers force the shape of the data to live implicitly in control flow, where it is fragile and unreadable. In Unrect, the shape is a first-class value: a composition of shapes and strategies that can be inspected, reused, and reasoned about independently of any particular spreadsheet.

Practical implications for API design:

- **Projections describe; they do not execute.** Constructing a projection should be side-effect free. Decomposition happens when the description is applied to a space (`Map`/`Apply`), not while the description is being assembled.
- **Strategies are the escape hatch for dynamism — but they are still declarative.** Variable-sized regions are handled by declaring *how* a boundary is determined (a predicate, a size rule), not by the user imperatively scanning for it. If a use case seems to require the user to write cursor logic, the right fix is a new strategy or combinator, not an imperative API.
- **Mapping is projection, not parsing.** By the time map functions run, decomposition is complete. Map functions read from an extent handed to them; they never influence or perform boundary decisions. A layout lambda runs once at declaration, with each child reading as the empty value of its type, and once per application with the values (2026-09-19, replacing the two-lambda slot form of 2026-09-17), and the two runs must declare the same children: a shape that depends on a value is a fault the first time it runs. The one bounded place where a shape depends on data is the bind rung, `Table(headerRows, eachRow: captions => …)`, which builds its row projection from the header it read and says so through `Opacity`.
- **Evaluate new features against this test:** does it let the user *say what the data looks like*, or does it make them *say how to walk it*? The former belongs in Unrect; the latter is a design smell. A second lens on the same question: could a writer execute this declaration — could it produce the file as well as read it? Declarations run backward; opaque code does not.
- **Explicit dimensions are the exception, not the rule.** Almost every boundary should be discovered by a strategy (predicate-based sizes, skip-while offsets). Hard-coded offsets/sizes are acceptable only for structurally fixed regions — e.g., a report header whose shape is part of the format's definition. A hard-coded count that merely *happens* to match today's file (a gap of 2 blank rows, a table 4 columns wide) is a fragility bug waiting for the next export.

## Architecture

### Core Metaphor

A "space" answers four canonical questions about a coordinate grid: its extent, and whether/what a cell at a coordinate holds. A "plane" is a rectangular region of one space — the space, a root origin, and an area — and cutting one is arithmetic: a composed origin over the *same* space, never a second space object. A "point" is one cell of a plane, addressed in the space's own root coordinates. A declared shape decomposes a space into a hierarchy of planes and points, projecting each part to a typed value as it goes. Strategies determine boundaries (sizes, offsets, row/column counts) by reading planes and points rather than by wrapping a subspace.

All five library projects multi-target `netstandard2.0;netstandard2.1` (since 2026-09-05), so the packages install on .NET Framework 4.6.1+ as well as .NET Core/5+. `Unrect.Tests` is `net8.0` everywhere and `net8.0;net48` on Windows — the net48 leg cannot run on Linux, so an OS condition in its csproj keeps Linux CI at net8.0; a net48 portability regression therefore surfaces only on Windows (`dotnet test src/Unrect.Tests/Unrect.Tests.csproj -f net48`). `Unrect.Benchmarks` stays net8.0.

**No `#if` forks — one source, both targets.** netstandard2.1-only constructs are removed rather than branched on: no default interface members (a strategy's whole-region answer is defined on the static `Unrect.Core.Scans` as the fold of its scan — `GetOffset`/`GetSize`/`GetArea`/`SelectRows`/`SelectColumns` are extension methods, not interface members), no `System.HashCode` (Core hand-rolls its combine to keep the package dependency-free), no `HashSet<T>.TryGetValue`, no `Dictionary<K,V>(IEnumerable<KeyValuePair<K,V>>)`. The two polyfills (`CallerArgumentExpressionAttribute`, `IsExternalInit`) are unconditional because *neither* netstandard has the type; a net5.0+ target is what would force an `#if`. Consequence: DIMs are no longer a seam option — a DIM on a published Core interface would compile everywhere and fail at run time on .NET Framework, so adding a member to a published Core interface is a breaking change with no escape hatch; type-testing is the whole capability recipe. That is exactly why `Plane<TSpace>` and `Point<TSpace>` are structs rather than interfaces: adding a member to one is a struct addition, not a breaking change, where the same growth on `ISpace` would break every implementer. The "a whole region and a stream cannot disagree" guarantee is by construction: a strategy has one spelling of its rule, the scan, and the whole-region answer is the fold of it.

### Data Flow

```
Excel file / 2D array
    -> adapter normalizes to a backend's own cell vocabulary   ("lexing": backend values -> one vocabulary)
    -> ISpace                                                  (the canonical four, over that vocabulary)
    -> Plane<TSpace> / Point<TSpace>                            (the region and cell a declaration is handed)
    -> ProjectionBuilders<TSpace> + Strategies                  (declarative description)
    -> projection.Map(space)                                   (hierarchical decomposition and projection, fused)
    -> typed objects
```

### Key Abstractions

- **`ISpace` / `Plane<TSpace>` / `Point<TSpace>`** — `ISpace` is the canonical four: `Area`, and `IsBlank`/`IsText`/`AsText` of a coordinate, root coordinates, bounds-checked with `OutOfBoundsException` on every member. `Plane<TSpace>` is the 2-D locator a projection is handed — a space, a root origin, an area; cutting one (`Slice`) is arithmetic over the same space, so decomposing a sheet into a hundred regions costs a hundred struct copies and no reads. `Point<TSpace>` is the 0-D locator a plane mints: one cell, addressed in root coordinates, compared by *address* rather than by value (`a == b` asks whether `a` and `b` are the same place, never whether they say the same thing). Growing either locator is a struct addition, not a breaking interface change — which is why the surface grows there and not on `ISpace`.
- **`GridSpace<T>` / `IValueCells<T>`** — the in-memory door for a homogeneous grid: `GridSpace.Create(int[,], isBlank:)`, `Create(double[,], isBlank:)`, `Create(string?[,])`, `Create(object?[,])` (heterogeneous, each value reading as the kind its CLR type implies) and the general `Create<T>(values, isBlank:, isText:, asText:)`. A cell's value is read back with `Point<IValueCells<T>>.Value()`.
- **Strategies** — Pluggable functions that determine spatial boundaries, now over `Plane<ISpace>`/`Point<ISpace>`:
  - `ISizeStrategy` — computes a `Size` from available space
  - `IOffsetStrategy` / `IAreaStrategy` — adapted from `ISizeStrategy`
  - `IRowStrategy` / `IColumnStrategy` — predicate-based row/column selection
  - Blankness conveniences: `OffsetStrategies.SkipBlankRows()`/`SkipBlankColumns()`, `SizeStrategies.RowsWhileAnyValue()`, `RowStrategies.TakeRowsWhileAnyValue()`, `ColumnStrategies.TakeColumnsWhileAnyValue()`
  - Explicit counts: `RowStrategies.TakeRows(n)` / `ColumnStrategies.TakeColumns(n)` — these throw `OutOfBoundsException` rather than clamp, consistent with `ExplicitArea`
  - `SizeStrategies.RowsWhileAny(predicate)` / `RowsWhileAnyValue()` + `.ToAreaStrategy()` (width = full available width, height = leading rows in which at least one cell satisfies the predicate) — the preferred way to size a data region instead of explicit bounds or `MaxArea`
  - `OffsetStrategies.SkipRowsWhileAll(predicate)` / `SkipRowsWhileAny(predicate)` declare a vertical offset such as "skip however many leading rows are entirely blank"; `SkipBlankRows()` is the zero-argument form. These do their primary work as the shape layer's defaults (e.g. `Table`'s placement); direct usage is pinned in `src/Unrect.Tests/Strategies/OffsetStrategyTests.cs`
  - `…Containing`/`…Where`/`…WithCell` are the closed canonical matchers; `RowSaying`/`ColumnSaying` is the opt-in widening onto what a cell *renders* rather than what it holds; `TakeRowsToText`/`TakeColumnsToText` are the row/column-strategy twins (renamed from `…ToValue`, since the rule is whole-cell text, trimmed, case-insensitive, text cells only — a different rule from "the value")
- **Projections (`Unrect.Projections`) — one vocabulary, `ProjectionBuilders<TSpace>`, and one mapping interface, `IProjectionDefinition<TSpace, TResult>`.** A file imports the vocabulary once, closed over the space every declaration in it is written against (`using static Unrect.Projections.ProjectionBuilders<Unrect.Spreadsheets.ISheetCells>;`), and every factory below that line is prefix-free. `projection.Map(space)` decomposes and projects in one call, and the projection is a reusable, thread-safe value safe to apply to many spaces at once.
  - **Leaves.** `Point()` and `AsText()` are the two canonical leaves, closed over `ISpace`'s four questions. `Point()` yields the cell's own address (`Point<TSpace>`) — the leaf for a reading this vocabulary does not name: a backend's own point-extension answers the rest (`Record(r => r["Amount"].Decimal())`), and it is also what a reader hands to its own complaint about a cell. `AsText()` yields what the cell says, unconditionally — a number renders its digits, a date its ISO form, so it is *total* and `Choice(AsText(), …)` is a degenerate choice (a narrower leaf belongs first, not `AsText`, which cannot fail). `Range`/`Row`/`Column` (through `CellBlock`/`CellStrip`), `Caption`, `Field`/`Fields` are unchanged in shape but hand back points now, never values: `Fields(...)` yields `IReadOnlyDictionary<string, Point<TSpace>>`, `Table()` (the exploratory dictionary rung) yields rows of the same. The six kinded leaves — `Text()`/`Decimal()`/`Integer()`/`Double()`/`Date()`/`Boolean()` — assert a kind and ship with the backend that can answer one: `Unrect.Spreadsheets`, over `ISheetCells`, via `SheetProjectionBuilders<TSpace>`/`SpreadsheetProjectionBuilders<TSpace>`.
  - **The leaf firewall.** The kinded leaves are closed over `ISheetCells`'s nine reads and mirror them 1:1; there is no `Long()`, `Money()` or `Enum<T>()`, now or later — each would be a new failure vocabulary and a new writer obligation. A conversion beyond that set is `Select` territory. The firewall's target moved from `CellValue` (Core) to a backend's own kind set (`Unrect.Spreadsheets.Cell`), but the law is unchanged: nothing is added to `Unrect` to serve a leaf, and adding a backend accessor does not add one on its own.
  - **Kind vs conversion.** A kind failure speaks the document's vocabulary — `expected Number at B4, found Text` — never the reader's; a `Number` that will not fit the CLR type asked for is reported as a conversion on a number that is really there. The vehicle is `CellProblem` (a sentence awaiting an address) returned by `ISheetCells`'s kinded `…At` methods, thrown as `CellReadException` by the point-extension that calls one, caught by the calling primitive and rethrown as a `ProjectionException` with the declaration path and the cell's A1 — the same template a kinded leaf and the reflective table binder both go through (`CellReading` in `Unrect.Spreadsheets`), so a `Decimal()` leaf and a bound `decimal` column cannot describe the same cell differently.
  - **Read failures are located, not accumulated.** A location comes from the plane or point that a failing read was handed, never from an origin threaded down through the tree — `ProjectionContext` no longer accumulates one at all. Every lambda-calling primitive (`SelectDefinition`, `StripDefinition`, `BlockDefinition`, `RecordDefinition`, the two `Table` lambda rungs, the layout bodies) catches a `CellReadException` at the same one seam and rethrows through `ProjectionContext.Reading`.
  - **Layouts** — `VerticalFlow(v => new R(v.Next(x), v.Next(y)))`, `HorizontalFlow(...)`, `Overlay(...)`. One lambda, run twice: at declaration every `Next` records its child and hands back the empty value of its type (0, `""`, an empty list; `default` otherwise), so `Children` is complete and ordered with the use site on each edge and `Opacity` is null; per application every `Next` hands back its child's value and the lambda's result is the layout's. The lambda may assemble, count, join and format; one that reads a cell or reaches into an object nothing built is refused where it is written (read in the leaf; compute in `Select`), and one whose shape depends on a value is a fault. The reflective table binder, which builds a user's type, is the one layout with an internal door (`LayoutCursor.Recording`) to skip building it on the declaration pass. A null child or an empty layout is refused where it is written. A flow divides its extent into bands; an overlay hands every child the whole extent.
  - **Tables — one `Table` family across two packages.** In `Unrect`, over any `ISpace`: `Table(headerRows: 1, eachRow: captions => ...)` — **the bind** — reads the header once per application, hands its `LabelMap` to a lambda that returns the projection for one record, and applies that description per row; `Table(headerRows:, eachRow: someProjection)` — the composed row-slot rung, `VerticalBands` under a discovered header, wrapped as one `UnitDefinition` so its failure path (`Table[3] -> 'eachRow'`) is identical to a leaf's; `Table()` — every row as `IReadOnlyDictionary<string, Point<TSpace>>`, for sight-reading an unfamiliar sheet; `Table(row => ...)`/`Table(view => ...)` — the lambda escape hatches over `TableRow<TSpace>`/`TableView<TSpace>`. In `Unrect.Spreadsheets`, over `ISheetCells`: `Table<T>()`/`Table<T>(bind => ...)` — the reflective rungs, captions bound to a type's members by `CaptionComparer`, composed through the core bind rung by reflection (`RowBinding`/`MemberPlan`); a nullable member tolerates a blank and still fails on the wrong kind, and one member type asserts nothing at all — `Point<TSpace>` is filled with the labelled cell's address, the escape hatch for a column the six kinds do not describe. A table declares no offset of its own: it starts where anything else does, at the left edge of what it is handed, and the columns its header leaves blank before the first caption are columns of the table with no label (`ColumnStrategies.TakeTableColumns`, internal: the FIRST ROW alone settles that lead, so a value further down column A cannot move where the table begins). Reads by name are unaffected; an index — `r[3]`, `bind.Column(t => t.Amount, 3)` — is a position from the table's left edge, and a declaration that wants to count from the first caption says so (`SkipToFirstNonBlankCell()`, `Right(n)`). `bind.Column(member, index)` binds the column a caption cannot reach (a blank header cell, one of two identical captions); the dictionary rung gives a captionless column with nothing in it no entry and still refuses one that holds values. Every rung accepts an `onBlank: BlankRowStrategy` (`Stop`/`Skip`/`Fault`/`Tolerate`) for a fully-blank body row; `Stop` (the default) is self-bounding, the others run to the enclosing edge.
  - **The default offset (2026-09-19).** A projection that does not say where it starts steps over the blank spans in front of it: a child of a flow or a repeat along its CONTAINER's axis (blank rows down a vertical one, blank columns across a horizontal one); the root and an overlay's children, which have no such axis, along the axis the run reads its source in (a column-major engine would skip blank columns there). Nothing moves across by default, and a declared anchor, distance or offset is taken at its word — `Down(1)` counts from exactly where the container put the child (`PlacementRules.DeclaresOffset` walks the wrapper chain; a node says what its children lead along through `DefinitionNode.LeadsChildren`, which its machine passes to `Start` and `CostReport` reads, so every `CostLine.Starts` says `Declared`/`AfterBlankRows`/`AfterBlankColumns`/`WhereItIsPut`). Tiler bands, a table's rows and a wrapper's inner start exactly where they are put. **A flow is a pattern and a strip is an index**: a flow divides a region into blocks with gaps of any size between them and a one-cell block is still a block, so a flow of leaves over a sparse row steps over the missing value; where a blank IS the value at a position, address by position (`Row(n, …)`, `Record`, an overlay with `Right(n)`, a table). Pinned by `DefaultOffsetTests`.
  - **Repetition and alternation** — `VerticalRepeat(item, separatedBy:, atLeast:)`/`HorizontalRepeat(...)`, `Choice`, `.Else`, `.Optional`. Every occurrence steps over the gap in front of it, so `separatedBy: BlankRows()` says nothing the default does not and `separatedBy:` is for a separator that is content; a repeat's next item that finds nothing but blanks is no next item, so a run ends quietly at a trailing blank band (a blank band is a gap, never a terminator — `.Until` ends a run at content). `VerticalBands(rows, each, onBlank:)`/`HorizontalBands(columns, ...)` is the tiler, not a repeat: a repeat repeats a *pattern* (each occurrence's extent discovered from the item), a tiler repeats a *fixed-dimension space* (a declared stride, nothing searched).
  - **Placement pipeline** — `On`/`Below`/`RightOf`/`OffsetBy`/`AfterBlankRows`/`AfterBlankColumns`/`SkipToFirstNonBlankCell`/`Down`/`Right`/`Until`/`UntilColumn`/`Heading`, entries on `ProjectionBuilders<TSpace>` that open a stage-typed pipeline (`On(mark).Down(1).Sized(...).Until(...).Heading(...).VerticalFlow(v => ...)`), plus the postfix twins on `IProjectionDefinition` in `ProjectionExtensions` (`.On`/`.Below`/`.RightOf`/`.OffsetBy`/…). Both spellings replay onto the same `Steps`; a contradiction (a second anchor, a second bound) is unspellable at compile time in the pipeline and refused at construction postfix. `.Named`, `.AsUnit(name)` (a composed rung's own unit label), `.AsScaffolding()` (marks a factory's internal plumbing so it folds out of a rendered path), `.Sized`, `.Padded`, `.Under(captions)` round out the modifiers.
  - **Matchers, rules and their lifts — the typed phantoms.** `RowWhere`/`RowWithCell`/`RowContaining`/`RowSaying` and the column twins, and every predicate-driven rule beside them (`RowsWhileAny`, `TakeRowsWhile`/`…To`/`…WhileAll`/`…WhileAny`, the `TakeColumns…` twins, `SkipRows/ColumnsWhileAll/Any`, `SelectSize`/`SelectArea`/`SelectOffset`, `RowsThenColumns`/`ColumnsThenRows`), read `Plane<TSpace>`/`Point<TSpace>` over the file's own space. **A canonical predicate asks the four questions; anything about kind or value is a typed predicate and names its space.** A matcher only locates and reports absence; `.On`/`.Below`/`.RightOf`/`.Until` decide what absence means. The demand rides in the return type through seven phantom interfaces — `IRowLandmark<TSpace>`/`IColumnLandmark<TSpace>` (unwrapped by `Landmark`) and `ISizeStrategy<TSpace>`/`IOffsetStrategy<TSpace>`/`IAreaStrategy<TSpace>`/`IRowStrategy<TSpace>`/`IColumnStrategy<TSpace>` (unwrapped by `Strategy`), none of them deriving from the plain form, all of them `in TSpace` so a rule built at `ISpace` flows into every file. Every member that takes one is doubled, so the demand is inferred with nothing annotated (`Sized(RowsWhileAny(p => p.Kind() == CellKind.Number))`, `On(RowWithFormula())`), and the lift unwraps once at construction — the engine receives the calculus's own object, never a wrapper, so the scan the engine gets is the rule's own. A rule unwrapped into the wrong space faults with `InvalidCastException`, which no tolerance boundary absorbs.
  - **Naming** — a child's path segment is the first of: its own `.Named`; the bare identifier it was written as at the capture site; otherwise its kind and 1-based position. Unchanged.
  - **`.Until(landmark)`** — unchanged: ends a shape's extent just before a content landmark, consuming the bound in full.

  Placement is applied by the engine's placement machine alone, exactly once, at every level including the root. Failures throw `ProjectionException` with the declaration path and an A1 cell location. `docs/vocabulary.md` is the complete operator survey. `CostReport.Of(definition)` is the dry run: per node, streams or holds and why.
- **Streaming (`Workbook`, in `Unrect.Spreadsheets`) — the second door onto a spreadsheet.** `Workbook.Open(path)` owns every cursor it opens and one string table; `book.Sheet(name)` is one forward pass over the sheet's own cursor — the engine drives it a row at a time and releases every row no open machine may still read, a cell read directly is loaded on the way to it, and a cell of a released row is a located read failure that says to read it inside the projection. Each call is a fresh pass; ask again to read again. The cost model is declaration-shaped: a table read one band per row holds a handful of rows, a shape that reads its extent whole holds its extent, and `CostReport` says which before a file is opened (see `docs/streaming.md`). **The cap:** `WorkbookOptions.BufferRows` is the most rows a pass may hold; exceeding it is a fault naming the innermost holder, never a degraded read. `Workbook.Statistics(sheet)` reports rows read, the peak held, the cap and the rows a survey took. **IO errors are faults, never tolerance** — a disk failure or a read after `Dispose` is classified a fault at every site that can absorb a foreign exception, so `.Optional()`/`.Else()`/`Choice` can never report a broken file as an absent section. User guide: `docs/streaming.md`.

## Design Direction

The forward design: a canonical coordinate substrate in Core (`ISpace`/`Plane`/`Point`, adapter-agnostic — spaces as "lexers" adapting backends into whatever vocabulary they need, with only the four canonical questions promised to everything above them), a backend-owned kind vocabulary for the formats that have one (`Unrect.Spreadsheets.Cell`), a document-level shape vocabulary (`Table`, `Repeat`/separator, `Choice`) built on the strategy calculus, capability seams for backend extras (formulas today, formatting next) under the rule that nothing in Core may require a capability, and an observability roadmap (named regions, decomposition trace, dry-run renderer, unconsumed-space warnings). New API work is checked against these principles. What is built and what remains is in **Where Work Left Off**.

## Where Work Left Off

The engine split is merged (master, `v0.3.0-alpha.3`; the scaffolder's `ScaffoldRecord`/`ScaffoldClass` and their leaf forms followed as `v0.3.0-alpha.4`). What stands: one interpreter, the push engine in `Unrect.Engine` — a definition builds its machine (`Build`), the placement machine around every child streams the vocabulary's own placements span by span or holds and replays them at close, a streamed source is released row by row from the oldest span an open machine may still read (each node's `Retains`, a repeat's `HeldFrom`), and `CostReport.Of(definition)` is the dry run. Every strategy contract is one member, `Begin`, handing back the scan that answers along the axis it is asked; the whole-region answer is the fold in `Scans`.

**The default offset** (branch `feature/default-blank-skip`, 2026-09-19): see Projections, above — one rule for where an undeclared projection starts, a table with no offset of its own, `Column(member, index)`, and a `CostReport` that says which start every node takes.

**Formatting** (2026-09-19, the owner's first real file: rows set in red are records deprecated upstream): `IStyleSpace` and `point.Font()`/`Fill()`, above. `Table<T>` carries a row-derived member through `bind.Column(f => f.IsDeprecated, row => row["Fund"].Font().Color == CellColor.Red)` — one member declared, every other still binding by caption; the binder is `TableBinding<TSpace, T>` so the row is a `TableRow` of the file's own space and the reading may ask anything that space answers, the member may be of any type (it is not one of the six kinds a column can be), it is not asked for a caption, and a failing read is located under `member 'IsDeprecated'`. Open on it: `CreateWithFormulas` now reads more than its name says, and the owner finds `Create` returning `ISheetCells` a poor name too — a rename of the doors (`Open` for the full space?) is for later; theme-colour resolution if a real file needs it. Each side pass re-reads the sheet's XML (values + formulas + formatting = three reads); that is the recorded trigger for owning one xlsx pass of our own (ExcelDataReader kept for `.xls`/CSV), considered and not planned — ClosedXML/EPPlus/NPOI are whole-workbook models that would end row-at-a-time streaming, and the Open XML SDK streams but hands back raw parts.

**Open for the owner, on record:** the strategy-layering collapse and the `RowMajorColumns` heuristic (see Open Design Questions), both awaiting discussion. The wording of the failure when a default skip runs off the end of its space (`an extent of 1x1 does not fit here`, one row past the last): throwing at the placement would stop a trailing `Table<T>().Optional()` over blank rows being absorbed as an absent section, so it wants a sketch first.

**Found, not fixed (2026-09-19, true on master too):** a streamed table NARROWER than the region it is handed holds every row until its last — measured 1,001 of 1,001 rows retained where a table that fills its region retains 2. The likely cause (read from the engine, not confirmed by experiment) is the width rule: "columns while any value" is a whole-block question, so rows wait in `ChildProjector._pending` until the width settles, which for a narrow table is its end. The fix the label reframe suggests: a HEADED table's columns are the header's, so its width can settle on the header row.

**Next, agreed with the owner:** header BANDS (`examples/multi-header-table.xlsx`: a merged "From"/"To" row over duplicate "Id"/"Code" captions) — `Table(2, r => r["From", "Id"].Integer())`, bands filled rightward to the next band caption (a merged cell is a value in its top-left cell and blanks beside it; merge ranges live in a separate list the reader exposes as `MergeCells`, an optional later refinement), a unique caption resolving without its band, then a nested type per band for `Table<T>`. Its own branch: it touches the label primitives. The owner's other sketch, instance indexing (`r["Id", 2]`, the second column captioned Id), is the cheaper cousin and unruled. After that, the horizontal table.

**Deferred, on record:** `Line<TSpace>` (the third locator; `CellStrip` stands in); the views as one family; header-side tables (`RowLabels`/`WithRowLabels`/a pivot — `LabelAxis.Row` is kept for the horizontal table); the non-generic `IProjectionDefinition` → Core (it speaks `Placement`/`Child`/`Axes`, so the charter would drag the projection layer into Core); the benchmark A/B write-up for the point substrate; a public row-source seam, async APIs and a streaming result type; the quadratic landmark search a growing prefix costs (`RowLandmarkOffsetStrategy` and `BoundedDefinition` hand the landmark the whole prefix on every span, and `IRowLandmark.FindRow` has no start index); a headerless `Table<T>` bound wholly by position.

**Roadmap:** header bands, the horizontal table, the decomposition trace, the dry-run renderer beyond `CostReport`, `IFormattingSpace`, `Line<TSpace>`.

## Example Usage

The linqpad scripts below are written in the tree's own vocabulary and reference the built
`Unrect.Engine.dll` beside the others, since `Map`/`Apply`/`MapWithDiagnostics` live there: a
declaration file imports `using static Unrect.Projections.ProjectionBuilders<TSpace>;` plus a
backend's own closed vocabulary (`SheetProjectionBuilders<TSpace>` or
`SpreadsheetProjectionBuilders<TSpace>`) once — the workbook scripts all name the FULL space,
`ISpreadsheetSpace` with `SpreadsheetProjectionBuilders`, opened by `CreateWithFormulas`, because a
script copied from one should start where `.Font()` and `Formula()` compile (a declaration's space
is fixed by those imports, not by how the workbook is opened: the owner's first `.Font()` failed to
compile over `ISheetCells`, reported as a `Column` overload not found) — a cell read is `point.Decimal()`/`.Text()`/…
or the canonical `point.AsText()`/`point.Value()`, and a table read by name is
`row["Amount"].Decimal()` rather than an accessor on a value the view used to hand back directly.

Zero point-level accessor calls — the reflective binder does the reading.
- `linqpad/investors-by-deal.linq` — parses `examples/investors-by-deal.xlsx`: one deal-block `VerticalFlow` (`Text()` over `Table<DealTransaction>()`), applied with `VerticalRepeat(deal)` — the gaps between deals need nothing said. All six captions bind with nothing declared.
